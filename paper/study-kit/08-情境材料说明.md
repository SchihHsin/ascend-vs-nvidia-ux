# 情境材料包说明（研究者准备，不给参与者）

将以下文件夹分别发给参与者，但必须确保不含研究假设、条件标签、评分或标准答案：

```text
scenario-a/
  starter/                    # AddCustom 最小工程骨架
  evidence/                   # 连续、可读、版本较清晰的公开资料
  logs/                       # 一段可解释但不要求解决的输出
  environment-manifest.md     # 部分环境信息，保留少量待发现事实

scenario-b/
  starter/                    # 已能运行的静态 AddCustom 工程片段
  evidence/                   # 动态 shape/Tiling/接入相关的跨材料入口
  logs/                       # 一段调用或编译输出
  environment-manifest.md     # 多版本或未展开的环境信息
```

研究者检查：

- 两个情境的目标、代码体量、阅读量和时间压力大致相当；
- A 的资料“连续、可读、版本较明确”，B 的资料“需要拼接或存在真实不确定性”，但不要把 B 做成无解题；
- 情境中所有公开资料记录 URL、抓取日期和版本；
- 不要以虚假的错误、假文档或人为阻断网络制造差异；
- 不要求参与者成功写出可运行代码，更不将计划质量等同于真实上卡成功率。
