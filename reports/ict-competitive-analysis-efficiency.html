01 / 选择课题 · 之前的痛点

传统分析由人工串起多条信息链，时间消耗在“找、等、对、拼”

旧报告中的开发者门户实跑、社区问题检索与 AI 可用性对照显示：高质量分析需要大量跨站搜集、条件核验、路径复现与内容整理。

01 / SEARCH

搜集相关来源

从官网、社区、文档、代码仓、媒体和案例中找到可用材料。

02 / VERIFY

逐项核查资料

核查链接、版本、区域、账号权限与页面状态是否真实可用。

03 / RUN

亲自体验产品

沿用户目标操作，记录入口、步骤、异常和恢复路径。

04 / COMPARE

横向整理差异

把同类页面、条件与体验放在一起比较，梳理差异和取舍。

05 / SYNTHESIZE

归纳发现与机会

把截图、链接、记录和外部反馈归纳为问题和机会。

06 / PRESENT

组织为设计表达

转化为报告、方向和 Demo，供设计与业务继续讨论。

等待成本

受限页面、动态内容和分散资料使单个证据的获得时间不可预测。

判断成本

材料多而口径不一，分析师需持续判断来源可信度、适用条件与可比性。

重复成本

项目一变，检索词、截图、路径和结论往往从头再做，难以沉淀。

02 / 把握现状 · 工作链

同一课题需要同时处理四类来源，转换成本层层累积

以计算领域为例，一项体验对照既要实跑产品路径，也要读取文档、检查代码和社区问题；无线、云服务等领域只是将来源组合换成方案、控制台、标准和案例。

06 / 10

分析师面对的是一个持续变化的证据面

每类材料各自解释一部分事实。当前工作主要依赖人工在不同站点和工具之间切换，再把零散信息关联到一个明确的用户任务或业务场景。

代码、API、配置、Issue 与样例CAN INSPECT
社区、客户案例、媒体与生态反馈CAN LISTEN
01 / DISCOVERY

发现被动

外部变化依赖临时搜索和个人订阅，难以持续覆盖重点竞品和主题。

结果：重要信号出现后，进入分析的时点不稳定。
02 / EVIDENCE

证据不连续

同一判断的页面、版本、截图和操作条件分散保存，难以快速复核。

结果：结论的可信度需要反复人工解释。
03 / SYNTHESIS

任务脱节

功能与资料容易被逐项罗列，用户如何完成关键工作没有被完整呈现。

结果：洞察难以直接进入体验设计。
04 / REUSE

资产沉没

报告交付后，材料、判断和方案分散在个人文件与不同项目中。

结果：下一个课题仍从零开始搜集。

CORE DIAGNOSIS

瓶颈是“从信号到设计判断”的人工接力

工具可以加快搜索和整理，设计师仍需保留对场景、证据强度、可比性和设计取舍的判断。

  • 01
    缺少主题化雷达
    信号难以按竞品、产业线、用户任务持续汇集。
  • 02
    缺少任务化分析单元
    体验、文档、社区证据没有围绕同一个工作目标组织。
  • 03
    缺少可调用知识资产
    证据、判断、方案与验证结果之间没有形成稳定连接。

03 / 设定目标 · 目标体系

以一个或两个产业线课题为试点，从竞品动向跟踪、专题分析到方案讨论跑通闭环；指标同时衡量产出速度、证据质量与对设计工作的帮助。

ANALYSIS CYCLE

更快形成可讨论的分析

让来源、截图、任务路径与判断在同一工作单元中组织，减少重新检索和材料拼接。

试点目标：从接到设计问题到形成专题分析初稿的周期缩短 40%；关键结论 90% 可回溯到来源与条件。
40%
KNOWLEDGE REUSE

让已有分析进入下一次工作

把产业线、竞品、任务、证据、洞察与方案作为可检索、可更新、可调用的设计知识。

试点目标：后续专题中至少 40% 的材料、判断或设计资产来自已沉淀的分析库。
总体目标：将 ICT 竞品分析从一次性、项目驱动的资料搜集，升级为面向产业线和用户任务的持续研究能力。
试点边界先选择计算、无线或云服务中的一个明确课题；覆盖一个核心用户任务、3–5 个重点竞品与一组可验证的设计问题。

90-DAY OPERATING LOOP

用三个周期建立基线、试点闭环和扩展判断

第 0–2 周选定产业线课题，盘点来源、已有资产与当前分析周期，建立基线。
第 3–6 周运行动向雷达和任务化研究单元，完成一轮竞品专题分析与设计讨论。
第 7–10 周将材料、判断和方案沉淀为可复用资产，比较试点前后的周期、覆盖和可追溯度。
第 11–12 周复盘目标达成与使用反馈，确定下一产业线的扩展范围和方法包调整。
