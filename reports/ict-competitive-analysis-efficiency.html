01 / 选择课题 · 当前不足

通用 skill 能完成一次分析，但尚未告诉它各领域“该分析什么、怎样判断”

现有骨架提供流程与专家视角；在 ICT 领域，若缺少任务、证据和判断标准的适配，搜集仍容易停留在资料罗列，分析结果也难以跨课题复用。

01 / SEARCH

搜集相关来源

从官网、社区、文档、代码仓、媒体和案例中找到可用材料。

02 / VERIFY

逐项核查资料

核查链接、版本、区域、账号权限与页面状态是否真实可用。

03 / RUN

亲自体验产品

沿用户目标操作，记录入口、步骤、异常和恢复路径。

04 / COMPARE

横向整理差异

把同类页面、条件与体验放在一起比较，梳理差异和取舍。

05 / SYNTHESIZE

归纳发现与机会

把截图、链接、记录和外部反馈归纳为问题和机会。

06 / PRESENT

组织为设计表达

转化为报告、方向和 Demo，供设计与业务继续讨论。

等待成本

受限页面、动态内容和分散资料使单个证据的获得时间不可预测。

判断成本

材料多而口径不一，分析师需持续判断来源可信度、适用条件与可比性。

重复成本

项目一变，检索词、截图、路径和结论往往从头再做，难以沉淀。

CORE DIAGNOSIS

通用 skill 缺少领域适配层

通用流程负责推进分析，领域方法包负责规定分析对象、证据选择、判断规则和设计出口，两者共同构成可从 1 扩展到 N 的能力。

  • 01
    领域任务包
    预置角色、任务链、关键决策与异常情况。
  • 02
    领域证据包
    定义需实跑、需精读、需检查和需补充的人机协作材料。
  • 03
    领域判断与出口
    形成对应的对比口径、洞察类型与设计行动方向。

03 / 方法论

通用分析引擎叠加领域方法包，形成从 1 到 N 的扩展结构

通用 skill 保持规划、搜集、洞察、可视化的统一流程；每个领域方法包补充该领域的任务、证据、判断与设计出口，使同一引擎能够稳定适配不同 ICT 场景。

KNOWLEDGE REUSE

让已有分析进入下一次工作

把产业线、竞品、任务、证据、洞察与方案作为可检索、可更新、可调用的设计知识。

试点目标：后续专题中至少 40% 的材料、判断或设计资产来自已沉淀的分析库。

90-DAY OPERATING LOOP

用三个周期建立基线、试点闭环和扩展判断

第 0–2 周选定产业线课题，盘点来源、已有资产与当前分析周期，建立基线。
第 3–6 周运行动向雷达和任务化研究单元，完成一轮竞品专题分析与设计讨论。
第 7–10 周将材料、判断和方案沉淀为可复用资产，比较试点前后的周期、覆盖和可追溯度。
第 11–12 周复盘目标达成与使用反馈，确定下一产业线的扩展范围和方法包调整。
