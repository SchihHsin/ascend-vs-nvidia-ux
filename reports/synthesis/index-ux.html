08/ AI 指标 · 架构映射
一次 AI 知识往返被拆解为可观测动作架构图中的关键动作对应一个或多个指标，用于衡量外部知识与模型先验能否共同支撑可靠作答。
01
模型先验与外部检索训练记忆与检索证据共同形成答案依据。
⑦ 模型自带知识衡量“训练记忆能否支撑答案”。
02
检索官方与第三方来源需要外部证据时，定位可用的官方页面与第三方信息。
① 官方可发现性 · ⑤ 第三方丰富度衡量“能不能找到足够入口”。
03
抓取 / 读取证据把网页正文、代码、表格取回来。
② 官方可抓取性 · ③ 正文详尽度衡量“取回后够不够用”。
04
判断证据是否充分看版本、来源一致性和是否需要再检索。
④ 版本清晰度 · ⑥ 第三方可信度 · ⑧ 检索成本衡量“证据能不能被放心采用”。
05
组织最终答案把证据合成为可执行步骤。
⑨ 版本可锁定性 · ⑩ 步骤可复现性 · ⑪ 综合置信度衡量“答案能不能落地”。
评分口径：关键动作被转化为可观测指标，并共同形成综合置信度。
指标计算方式：①–⑩ 定义各项可观测得分，最终形成综合置信度⑪
AI 侧 · 指标体系 · 「定义与计算理由」
09/ AI 指标 · 计算理由
指标 ①–⑩：将实测记录换算为可比较的 1–5 分每项指标采用明确的观测输入与分档规则，避免以主观印象代替证据。
计算模式
官方证据类 串行相乘官方链 OFF = (①/5)×(②/5)×(③/5)；任一环断掉都会打折
①
官方可发现性 触达首条官方=5；首屏靠后=4/3；二次改词才找到=2。
②
官方可抓取性 触达正文可直接取回=5；部分可取回=4；仅返回导航和标题=2；完全受限=1。
③
官方正文详尽度 质量穷尽=5/4；主路径=4/3；概述=3；片段=2；抓取受阻记 BLOCKED。
④
版本清晰度 质量版本无关/单版本=5；矩阵=4；双轴可锁=3；多版本散乱=2。
生态互证类 数量×可信第三方链 SEC = (⑤/5)×(⑥/5)；第三方少或不可信都会削弱互证
⑤
第三方丰富度 触达去重来源数：≥6=5；5=4；3–4=3；1–2=2；0=1。
⑥
第三方可信度 质量来源可信均分 + 一致性；再扣时效风险（中位月龄≤36不扣、≤48扣0.25、>48扣0.5）和平台重复风险（独立平台占比≥0.8不扣、≥0.6扣0.25、更低扣0.5）。
模型先验类 单独成链模型先验链 OWN = ⑦/5；训练知识可独立支撑，但受技术迭代影响
⑦
模型自带知识 质量先按训练覆盖给1–5档；再按技术迭代速度扣截止风险：稳定不扣，中等迭代扣0.25，alpha/RC高频变化扣0.5，防止模型用过期记忆作答。
检索过程类 过程成本⑧先计算检索成本，再映射为 1–5 分；进入综合分时只作为成本因子
⑧
检索成本 成本成本 = 检索轮数 + 0.5×成功抓取 + 4×抓取失败。检索轮数是基准单位；成功抓取只是核验证据，低于重搜，按半轮计；抓空会触发“识别空正文 → 换词/找镜像 → 重抓 → 复判”，按返工链路计。
答案产出类 结果解释⑨⑩ 不进入 ⑪；用于说明 AI 最终答案能否落地
⑨
版本可锁定性 产出精确版本=5；基本可定=4；范围可定=3；无法定死=2。
⑩
步骤可复现性 产出照抄即跑=5；替参数=4；需小修=3；仅骨架=2。
⑪ 综合分回答：AI 有没有足够可靠的证据来作答

①–⑩ 采用 1–5 可解释档位：5 表示几乎不阻碍 AI 作答，3 表示需要拼接或判断，1/2 表示会明显拖累答案可靠性。随后再计算官方、第三方、模型自带知识三条证据链。

先算三条证据链各自是否成立官方链 OFF = (①/5)×(②/5)×(③/5)
第三方链 SEC = (⑤/5)×(⑥/5)
模型先验链 OWN = ⑦/5

官方链是“搜得到、抓得到、正文够用”串起来；第三方链是“数量够、可信度够”共同成立。

再算至少一条证据链可用的概率K = 1-(1-OFF)(1-SEC)(1-OWN)

OFF / SEC / OWN 分别对应官方链、第三方链、模型先验链；只要有一条足以支撑答案，就能形成可靠回答。

最后扣掉版本混乱和检索费力的影响综合 = K × (0.7+0.3×④/5) × (0.9+0.1×⑧/5)

30% 用在版本因子，10% 用在成本因子；⑧先用检索轮数、成功抓取、抓取失败算出成本档位，再进入综合公式。⑨⑩保留为答案结果说明。

依据要把差异归因到「生态」，就得让生态成为唯一变量，任务 / 模型 / 评分口径全部固定。
做法同一套任务在 CUDA / 英伟达 与 CANN / 昇腾 各实测一遍，同题、同 Agent、同评分。
指标每项都是「昇腾实测 vs 英伟达实测」的成对值，差值即生态差距——非单边主观分。
依据 · R. A. Fisher《实验设计 The Design of Experiments》1935
触达›质量›成本›产出
拆解框架
知识价值链information foraging
依据知识要起作用，得走完「被找到 → 被取到 → 被用上」整条链，任一关断掉价值就打折。
做法把「能不能用上知识」拆成四段分别测：触达 → 质量 → 成本 → 产出。
指标这条链决定了指标的分层结构：①②触达 / 质量 / ⑧成本 / ⑨⑩产出，逐关评。
依据 · Pirolli & Card “Information Foraging” · Psychological Review 1999

可发现 / 可取回findability / retrievability

# ai-usability-benchmark

一份可分享的 Claude Code Skill：衡量「一个会实时检索的 AI 助手，

回答某个生态的开发任务时，知识从哪来、可用性如何，

与另一个成熟生态相比差在哪」。

在若干开发者任务上，对两个生态各实测检索一遍（web_search / web_fetch），

按统一的 11 项指标量化打分、记录每一步、产出可下钻的对照矩阵。

默认对照：受测生态 = CANN（昇腾），基线生态 = CUDA（NVIDIA）。

视角是「会检索的 AI 助手」，不是「这个栈好不好用」。

AI 助手只能搜→抓→读正文→拼答案。

# Journey Touchpoint Analysis

Use this skill to turn "pretend I am a user trying to complete a task on this site"

into a rigorous, visual report: journey map, touchpoint cards, annotated screenshots,

scoring, heatmap, and recommendations.

This skill was distilled from the Ascend vs NVIDIA developer-portal analysis.

Core Output: Scenario and persona; Lifecycle journey; Touchpoint inventory;

Evidence: real screenshots and source URLs for both sides of a comparison;

Annotated click path: arrows and labels showing where the user actually clicks or looks;

Scoring: per-touchpoint scores based on explicit friction metrics, not vibes.
